### A. Hierarchical Clustering Needs a Rule for Cluster-to-Cluster Distance
- The lecture begins with the open question from lecture 24: once clusters contain more than one point, how do we know which two clusters are closest? A simple option is to represent each cluster by a centroid, which is the average point in the cluster, and then compare centroids. [PDF: ics604-S26-lec25-Clustering-2.pdf p2-p3]; [NB1: ics604-24-25_clustering.ipynb cells 30-33]
- The centroid idea works only when averaging makes sense. The lecture gives DNA sequences as the counterexample: we can compute distances between DNA strings, but there is no obvious average DNA string to use as a centroid. [PDF: ics604-S26-lec25-Clustering-2.pdf p3]; [NB1: ics604-24-25_clustering.ipynb cell 33]
- Linkage criteria solve this by defining distance between clusters using point-to-point distances. Single linkage uses the minimum distance between one point in each cluster. Complete linkage uses the maximum distance. Average linkage uses the average of all cross-cluster point distances. Ward's method chooses the merge that causes the smallest increase in within-cluster variance. [PDF: ics604-S26-lec25-Clustering-2.pdf p4]; [NB1: ics604-24-25_clustering.ipynb cells 33-34]
- The rendered linkage slides show why this choice matters. On curved two-moon data, single, complete, and average linkage can produce different partitions even with the same number of clusters. On simulated blob data, the `AgglomerativeClustering` example compares `single`, `complete`, `average`, and `ward`; Ward's method gives a more balanced set of cluster sizes in that example. [PDF: ics604-S26-lec25-Clustering-2.pdf p4-p5]; [NB1: ics604-24-25_clustering.ipynb cell 34]
- The lecture's summary is balanced. Hierarchical clustering is easy to understand and gives an interpretable tree view, but it is computationally intensive. It can also be hard to decide where to cut the dendrogram, especially when the tree has no obvious large gap. [PDF: ics604-S26-lec25-Clustering-2.pdf p5]; [NB1: ics604-24-25_clustering.ipynb cell 35]

#### In Layman's Terms
- Hierarchical clustering needs a rule for "which groups are closest?" Different linkage rules answer that question differently, so they can produce different clusters from the same data. There is no free rule that is best for every dataset. [PDF: ics604-S26-lec25-Clustering-2.pdf p3-p5]; [NB1: ics604-24-25_clustering.ipynb cells 33-35]

#### Language Bridge
- `AgglomerativeClustering(n_clusters=5, linkage=linkage)` keeps the algorithm fixed while changing only the linkage setting. In programming terms, the loop is a parameter sweep: same input data, same class, different configuration values. [PDF: ics604-S26-lec25-Clustering-2.pdf p5]; [NB1: ics604-24-25_clustering.ipynb cell 34]

### B. K-Means Alternates Between Assignment and Centroid Updates
- K-means is introduced as a popular method for splitting data into a predefined number of groups. The analyst chooses `k`, initializes `k` cluster representatives called centroids, assigns each point to its closest centroid, recomputes the centroids, and repeats assignment and recomputation until the result is stable. [PDF: ics604-S26-lec25-Clustering-2.pdf p6-p7]; [NB1: ics604-24-25_clustering.ipynb cell 36]
- The rendered slides show the core geometry. Points are "painted" with the color of the closest centroid, and the boundary between clusters is based on nearest-center regions. After reassignment, the centroids move to the average location of the points currently assigned to them. [PDF: ics604-S26-lec25-Clustering-2.pdf p6-p7]; [NB1: ics604-24-25_clustering.ipynb cells 36-41]
- The notebook generates blob-shaped data with `make_blobs(..., random_state=0)`, then fits `KMeans(n_clusters=4, n_init=10)`. The rendered slide shows four centroids, decision boundaries, and an inertia value of about `513.85`. In scikit-learn, `kmeans.score(X)` is the negative of inertia, so the displayed score is about `-513.85`. [PDF: ics604-S26-lec25-Clustering-2.pdf p8]; [NB1: ics604-24-25_clustering.ipynb cells 38-41]
- Inertia is the sum of squared distances from each point to its assigned cluster center. Lower inertia means points are closer to their assigned centroids, but inertia always tends to improve as `k` increases. The lecture therefore plots inertia against `K` and looks for an elbow, where improvement starts slowing down. The rendered example points to an elbow around `K = 4`. [PDF: ics604-S26-lec25-Clustering-2.pdf p8]; [NB1: ics604-24-25_clustering.ipynb cell 42]
- The lecture lists several practical cautions. K-means is non-deterministic because different initial centroids can lead to different final assignments. It also assumes Euclidean-style numerical data where centroids are meaningful, so it is not a natural fit for categorical or non-Euclidean data. K-medoids is named as an alternative where each cluster representative is an actual observed point with the smallest average distance to the other points in its cluster. [PDF: ics604-S26-lec25-Clustering-2.pdf p9]; [NB1: ics604-24-25_clustering.ipynb cell 43]
- K-means is still useful because it is often efficient. The lecture says it usually converges in a small number of iterations, often around `10` to `50`, though poor initialization can occasionally make convergence slower. [PDF: ics604-S26-lec25-Clustering-2.pdf p9]; [NB1: ics604-24-25_clustering.ipynb cell 43]

#### In Layman's Terms
- K-means is a repeat-until-stable loop. Guess centers, assign points to the closest center, move each center to the middle of its assigned points, and do it again. It works well when clusters look like compact blobs, but it is less reliable when the data shape or data type does not match that assumption. [PDF: ics604-S26-lec25-Clustering-2.pdf p6-p9]; [NB1: ics604-24-25_clustering.ipynb cells 36-43]

#### Language Bridge
- `KMeans(n_clusters=4, n_init=10).fit(X)` follows the standard scikit-learn workflow. The object stores learned results such as `cluster_centers_`, `labels_`, and `inertia_` after fitting. These are like public fitted-state fields on the model object. [PDF: ics604-S26-lec25-Clustering-2.pdf p8]; [NB1: ics604-24-25_clustering.ipynb cells 39-40]

### C. Silhouette Scores Measure Cohesion and Separation Together
- The lecture defines a good clustering result using two ideas. Cohesion means points within the same cluster are close to each other. Separation means points in different clusters are far apart. A good solution should have small within-cluster distances and large across-cluster distances. [PDF: ics604-S26-lec25-Clustering-2.pdf p10]; [NB1: ics604-24-25_clustering.ipynb cell 44]
- The silhouette coefficient gives a point-level score for this tradeoff. For point `i`, `a_i` is the average distance from that point to other points in its own cluster, and `b_i` is the smallest or average distance from that point to points in another cluster. The lecture wants `a_i` small and `b_i` large. [PDF: ics604-S26-lec25-Clustering-2.pdf p10]; [NB1: ics604-24-25_clustering.ipynb cell 45]
- The formula is `S_i = (b_i - a_i) / max(a_i, b_i)`. The score ranges from `-1` to `1`. Positive values mean the point fits its cluster better than another cluster. Values near zero suggest boundary cases. Negative values suggest poor clustering because the point is closer to another cluster than to its assigned one. [PDF: ics604-S26-lec25-Clustering-2.pdf p11]; [NB1: ics604-24-25_clustering.ipynb cell 45]
- The notebook implements the idea using simple helper functions. `compute_a()` loops over points in the same cluster and averages Euclidean distances. `compute_b()` finds the minimum distance from the target point to points in another cluster. `pt_silhouette()` combines the two values using the silhouette formula. [PDF: ics604-S26-lec25-Clustering-2.pdf p11]; [NB1: ics604-24-25_clustering.ipynb cells 46-48]
- Cluster-wide and overall scores are built by averaging point-level silhouette values. The rendered examples show the score falling as clusters overlap more: a clearly separated example has an overall score about `0.7166`, a messier one is about `0.4199`, and a badly assigned case is about `-0.3851`. [PDF: ics604-S26-lec25-Clustering-2.pdf p12-p13]; [NB1: ics604-24-25_clustering.ipynb cells 49-56]
- The lecture then uses silhouette scores to choose the number of clusters. For each candidate `k`, run the clustering algorithm, compute the overall silhouette score, and look for a peak. Because K-means depends on random initialization, the lecture asks why we run it several times for each `k`: the reason is to avoid trusting one unlucky initialization. [PDF: ics604-S26-lec25-Clustering-2.pdf p13]; [NB1: ics604-24-25_clustering.ipynb cells 57-58]

#### In Layman's Terms
- A silhouette score asks, "Does this point look more like its own group than the nearby other groups?" A high positive score is good. A score near zero means the point sits near a boundary. A negative score means the point may be in the wrong group. [PDF: ics604-S26-lec25-Clustering-2.pdf p10-p13]; [NB1: ics604-24-25_clustering.ipynb cells 44-58]

#### Language Bridge
- The notebook's silhouette code is intentionally procedural: explicit loops, a list of distances, and a final average. That matches the lecture goal of seeing the formula directly before relying on `sklearn.metrics.silhouette_score`. [PDF: ics604-S26-lec25-Clustering-2.pdf p11-p13]; [NB1: ics604-24-25_clustering.ipynb cells 46-58]

### D. Mixture Models Treat Clusters as Probability Distributions
- The mixture-model section starts with a spending example. Suppose male and female purchases have different spending patterns, but the sales data do not include gender labels. K-means can force the data into clusters, but a mixture model instead represents each group as a probability distribution, such as a Gaussian with its own mean and standard deviation. [PDF: ics604-S26-lec25-Clustering-2.pdf p14-p15]; [NB2: ics604-25-26_mixture_models.ipynb cells 1-4]
- The notebook simulates the example with `np.random.seed(45)`. It generates `387` male purchases from a normal distribution with mean `204` and standard deviation `31`, and `422` female purchases from a normal distribution with mean `257` and standard deviation `28`. The combined histogram hides some of the two-group structure because the groups overlap. [PDF: ics604-S26-lec25-Clustering-2.pdf p15-p16]; [NB2: ics604-25-26_mixture_models.ipynb cells 4-6]
- KDE makes the mixture shape easier to see than a histogram. The lecture says the total sales distribution has two peaks, and the rendered slide shows that the peaks become much clearer when the two component means are farther apart, such as means `150` and `300`. [PDF: ics604-S26-lec25-Clustering-2.pdf p16-p17]; [NB2: ics604-25-26_mixture_models.ipynb cells 6-8]
- A finite mixture model represents the observed total distribution as a blend of a fixed number of component distributions. The lecture gives natural examples: professional versus general app spending, or fast versus slow patient recovery groups. These components can be thought of as clusters, but they are statistical clusters rather than hard regions only. [PDF: ics604-S26-lec25-Clustering-2.pdf p18]; [NB2: ics604-25-26_mixture_models.ipynb cell 9]
- The notebook plots separate KDE curves for the male and female samples, then compares those component curves with the KDE of the combined data. The rendered slide makes the key idea visible: the combined curve is not a new single source, but the result of overlapping component sources. [PDF: ics604-S26-lec25-Clustering-2.pdf p19]; [NB2: ics604-25-26_mixture_models.ipynb cells 10-13]

#### In Layman's Terms
- A mixture model says the data may look like one pile only because several groups were blended together. Instead of pretending there is one average group, we model the hidden groups and how much each one contributes. [PDF: ics604-S26-lec25-Clustering-2.pdf p15-p19]; [NB2: ics604-25-26_mixture_models.ipynb cells 3-13]

### E. K-Means Gives Hard Labels, but Mixture Models Keep Uncertainty
- The lecture next tries K-means on the one-dimensional spending data. Since `sales_total` is a concatenation of `sales_males` and `sales_females`, the notebook creates true labels with zeros for the `387` male points and ones for the `422` female points. [PDF: ics604-S26-lec25-Clustering-2.pdf p20]; [NB2: ics604-25-26_mixture_models.ipynb cells 14-15]
- The notebook reshapes the one-dimensional sales data with `sales_total.reshape(-1, 1)` before fitting `KMeans(n_clusters=2, n_init=5)`. The rendered slide shows learned centers near `259.58` and `194.81`, which line up with the higher-spending and lower-spending groups. [PDF: ics604-S26-lec25-Clustering-2.pdf p21]; [NB2: ics604-25-26_mixture_models.ipynb cells 16-19]
- Because K-means labels are arbitrary names, the notebook flips the predicted labels with `1 - y_predicted` before comparing to `y_true`. The rendered slide shows an accuracy of about `0.8109`. The important lesson is not the exact accuracy, but that hard labels make mistakes in the overlap region. [PDF: ics604-S26-lec25-Clustering-2.pdf p21]; [NB2: ics604-25-26_mixture_models.ipynb cells 20-22]
- The lecture then explains why K-means is impractical for this kind of problem. It works best with blob-shaped data and spherical boundaries centered on means. It struggles with overlapping clusters, and it gives no confidence value for a point near the boundary. [PDF: ics604-S26-lec25-Clustering-2.pdf p22]; [NB2: ics604-25-26_mixture_models.ipynb cell 23]
- The desired replacement is a method that includes assignment uncertainty. Instead of saying a point is fully male-like or fully female-like, the model should be able to assign probabilities, such as stronger probability under one distribution and weaker probability under the other. [PDF: ics604-S26-lec25-Clustering-2.pdf p22]; [NB2: ics604-25-26_mixture_models.ipynb cell 23]

#### In Layman's Terms
- K-means draws a hard line. A mixture model allows a gray area. If a purchase value sits where the two spending groups overlap, a soft probability is more honest than pretending the answer is certain. [PDF: ics604-S26-lec25-Clustering-2.pdf p20-p22]; [NB2: ics604-25-26_mixture_models.ipynb cells 14-23]

#### Language Bridge
- `reshape(-1, 1)` turns a one-dimensional NumPy array into a two-dimensional matrix with one feature column, which scikit-learn expects for model fitting. The `-1` means "infer the number of rows from the data length." [PDF: ics604-S26-lec25-Clustering-2.pdf p21]; [NB2: ics604-25-26_mixture_models.ipynb cell 16]
- K-means cluster labels are identifiers, not semantic labels. That is why `1 - y_predicted` is valid here: it swaps label names so the predicted labels line up with the lecture's `0 = male` and `1 = female` convention. [PDF: ics604-S26-lec25-Clustering-2.pdf p21]; [NB2: ics604-25-26_mixture_models.ipynb cell 20]

### F. A Mixture Distribution Has a Generative Story and Weighted Component Densities
- The lecture improves the spending example by making group membership random. Instead of assuming the exact number of male and female observations is known ahead of time, the model should include a parameter for the group proportion. The slide gives the example of sampling gender from a binomial-style process with a population proportion. [PDF: ics604-S26-lec25-Clustering-2.pdf p23]; [NB2: ics604-25-26_mixture_models.ipynb cell 24]
- The rendered generative diagram shows the story: an enrolled person first gets a hidden group sampled using probability `p`; if the group is male, the transaction is sampled from a Gaussian with parameters `mu_1` and `sigma_1`; if the group is female, the transaction is sampled from a Gaussian with parameters `mu_2` and `sigma_2`. [PDF: ics604-S26-lec25-Clustering-2.pdf p23]; [NB2: ics604-25-26_mixture_models.ipynb cell 25]
- The notebook simulates this generative process with `np.random.seed(42)` and `male_female_prop = 0.45` for `1000` people. In that run, the random draw produced `439` male-sampled observations and `561` female-sampled observations, which is close to but not exactly `45%` and `55%` because sampling is random. [PDF: ics604-S26-lec25-Clustering-2.pdf p24]; [NB2: ics604-25-26_mixture_models.ipynb cells 26-30]
- The notebook then separates the component KDEs and the total KDE. This reinforces the idea that the total density is built from the component densities. [PDF: ics604-S26-lec25-Clustering-2.pdf p24-p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 27-30]
- The notebook states the mixture density as a weighted sum: `pdf(x) = pi * pdf_male(x) + (1 - pi) * pdf_female(x)`. Here, `pi` is the mixing coefficient, meaning the share of the population assigned to the male component. The code later builds a theoretical total curve by weighting the male and female theoretical normal densities by their sample proportions. [PDF: ics604-S26-lec25-Clustering-2.pdf p24-p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 31-37]
- The lecture ends with a setup question: if we know the means and standard deviations of two populations, how should we decide which population a new observation came from? The notebook frames the answer as comparing the probability density of the observation under each Gaussian. For the example point `x = 300`, the next step is to compare how much density each population assigns to that value. [PDF: ics604-S26-lec25-Clustering-2.pdf p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 38-40]

#### In Layman's Terms
- A mixture model tells a story about how the data could have been made. First choose a hidden group using a probability. Then draw the observed value from that group's distribution. Since we only see the final value, the model has to reason backward about both the hidden group and the group parameters. [PDF: ics604-S26-lec25-Clustering-2.pdf p23-p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 24-40]

#### Language Bridge
- The generative simulation in cell 26 is intentionally plain Python: a `for` loop, `np.random.choice()` for the hidden group, and an `if`/`else` branch to sample from the matching normal distribution. In object-oriented terms, it is manually simulating the data factory before later fitting a model to its output. [PDF: ics604-S26-lec25-Clustering-2.pdf p24]; [NB2: ics604-25-26_mixture_models.ipynb cell 26]
- `sp.stats.norm.pdf(x_axis, mean_males, std_males)` evaluates the Gaussian density curve for many possible spending values. It does not return probabilities for exact points; it returns density heights, which are compared and weighted to build the mixture curve. [PDF: ics604-S26-lec25-Clustering-2.pdf p25-p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 32-37]

### G. The New Notebook Continues into EM and Gaussian Mixture Models
- The new notebook continues after the PDF's setup question. It names the unknown Gaussian Mixture Model parameters: the male mean and standard deviation, the female mean and standard deviation, and the population proportion for the two groups. The core problem is circular: if the labels were known, the parameters would be easy to estimate; if the parameters were known, the labels would be easier to infer. In real mixture modeling, both are unknown. [PDF: ics604-S26-lec25-Clustering-2.pdf p22-p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 40-42]
- The notebook answers the `x = 300` question by evaluating the Gaussian density under each component and normalizing the two density values so the membership values sum to `1`. This is the soft-assignment idea: a point can partly belong to more than one component instead of receiving only one hard label. [PDF: ics604-S26-lec25-Clustering-2.pdf p22-p26]; [NB2: ics604-25-26_mixture_models.ipynb cells 43-46]
- Expectation-Maximization, often called EM, is the iterative algorithm used here. In the E-step, the model uses the current parameters to estimate each point's component membership probabilities. In the M-step, it treats those probabilities as weights and updates the component parameters, such as means and standard deviations. The process repeats until the estimates stabilize. [NB2: ics604-25-26_mixture_models.ipynb cells 47, 49-54]
- The notebook connects EM back to K-means. K-means can be viewed as an EM-like method with hard assignments: the E-step assigns each point to the nearest center, and the M-step recomputes each center from its assigned points. A Gaussian Mixture Model is softer because each point can have fractional membership in each component. [PDF: ics604-S26-lec25-Clustering-2.pdf p6-p7, p22]; [NB2: ics604-25-26_mixture_models.ipynb cells 48, 56]
- The EM section also warns about assumptions. If the prior probabilities of the clusters are not equal, the model should estimate those mixing proportions from the current soft assignments. A prior of zero creates a dead cluster because no point can be assigned to it. EM can also settle at a local optimum, so the notebook recommends multiple initializations, just as K-means is often run more than once. [PDF: ics604-S26-lec25-Clustering-2.pdf p9, p13]; [NB2: ics604-25-26_mixture_models.ipynb cell 55]
- The notebook then demonstrates `GaussianMixture` from scikit-learn on two-dimensional data. It compares a K-means fit with `GaussianMixture(n_components=2, covariance_type="spherical", max_iter=1000)` and a second Gaussian mixture using the default full covariance. It also uses `predict_proba()` to get confidence-like membership probabilities and plots points with larger marker sizes when the model is more confident. [NB2: ics604-25-26_mixture_models.ipynb cells 57-74]
- The last notebook topic asks how many Gaussians should represent the data. This is similar to choosing `k` for K-means, but Gaussian Mixture Models have a probability objective: compare how likely the observed data are under different candidate models. The notebook notes that practical model choice often also needs a penalty for models that are too complex. [PDF: ics604-S26-lec25-Clustering-2.pdf p13]; [NB2: ics604-25-26_mixture_models.ipynb cell 75]

#### In Layman's Terms
- EM is a repeat-until-stable method for hidden groups. First guess how much each point belongs to each hidden group. Then update the bell curves using those partial memberships. Repeat until the guesses and curves stop changing much. [NB2: ics604-25-26_mixture_models.ipynb cells 47-56]

#### Language Bridge
- `GaussianMixture(...).fit(X)` follows the same model-object pattern as `KMeans(...).fit(X)`. After fitting, `.predict(X)` gives hard labels, while `.predict_proba(X)` gives one probability per component for each row. [NB2: ics604-25-26_mixture_models.ipynb cells 61-74]
- `covariance_type="spherical"` means each component has one variance value, so its shape is more restricted. A full covariance model can use a more general covariance matrix for each component, which can better fit stretched or tilted clusters. [NB2: ics604-25-26_mixture_models.ipynb cells 61, 69-71]
